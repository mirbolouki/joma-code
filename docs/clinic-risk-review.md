# گزارش ممیزی ریسک استقرار «مدیریت مطب» — تست ۳۶۰ درجه
**تاریخ: ۳۰ شهریور ۱۴۰۵ | روش: diff خط‌به‌خط با زیپ اصلی + grep روی کد واقعی (بدون حدس)**

## ۱. خلاصه اجرایی
- **فایل جدید:** ۱۲ عدد — هیچ‌کدام توسط جریان‌های قبلی لود/اجرا نمی‌شوند (به‌جز یک فایل CSS که ۱۰۰٪ زیر `body.clinic-page` اسکوپ شده و روی صفحات قبلی صفر اثر دارد — با grep راستی‌آزمایی شد).
- **فایل قبلی تغییریافته:** ۵ عدد (bootstrap به حالت اصلی برگشت = ۰ خط). همه تغییرات شرطی‌اند و برای کاربران/صفحات قبلی مسیر کد دقیقاً مثل قبل اجرا می‌شود (جدول بخش ۲).
- **داده:** فقط ۱۰ کلید خالی به store.json اضافه می‌شود (merge افزودنی)؛ ثابت شد هیچ کدی روی کل store حلقه نمی‌زند. رول‌بک امن است.
- **۳ ریسک واقعی پیدا و رفع شد** (بخش ۳).
- **۴ سؤال باز** درباره محیط واقعی شما (بخش ۵) — بدون جواب این‌ها، دستور دیپلوی نهایی را نمی‌دهم.

## ۲. جدول تغییرات فایل‌های قبلی (همه با diff واقعی)

| فایل | تغییر | تحلیل ریسک برای کارکرد فعلی |
|---|---|---|
| `index.php` (+۱۸) | ۱۰ route جدید + لود تنبل `clinic.php` فقط اگر `p=clinic_*` | صفحات قبلی: شرط همیشه false ← صفر اثر. حتی اگر `clinic.php` خطا داشته باشد، صفحات قبلی بالا می‌آیند. |
| `includes/layout.php` (+۷۱، ~۲ خط شرطی) | منوی مطب + کلاس بدنه + مخفی‌کردن هم‌مسیر برای نقش مراجع + لینک CSS اسکوپ‌شده | نقش `member`: خروجی HTML یکسان (همه ifها false). نقش `admin`: فقط منوی مطب اضافه می‌بیند (مطلوب). متغیرهای جدید (`$__clinic_*`) با متغیرهای قبلی تداخل ندارند (grep شد). |
| `includes/helpers.php` (+۳) | معافیت صفحات/کاربران مطب از گیت خلق‌وخو | کاربران قبلی + صفحات قبلی: هر دو شرط false ← رفتار یکسان. |
| `pages/login.php` (+۱۲/−۱) | چک `active` + عدم سید جوما برای نقش مطب + ریدایرکت مطب | کاربران موجود (`member/admin` بدون فیلد active): هر سه شرط false ← مسیر قدیمی دقیقاً. |
| `includes/store.php` (+۱۸) | ۱۰ کلید جدید + ۳ نقش جدید در permissions | `member/admin`: خروجی permissions یکسان. کلیدها با merge اضافه می‌شوند؛ خواندن/نوشتن قبلی بی‌تغییر. |
| `includes/bootstrap.php` | **۰ خط** (برگردانده شد به اصل، diff خالی ✅) | — |

## ۳. ریسک‌هایی که پیدا و رفع شدند
1. **بازنویسی `.hint` جوما** (واقعی): `clinic.css` من `.hint` سراسری داشت و چون بعد از `joma.css` لود می‌شد، فونت صفحات ثبت‌نام را عوض می‌کرد. **رفع:** کل فایل زیر `body.clinic-page` اسکوپ شد + کلاس بدنه فقط در صفحات مطب. (۸ تداخل مشابه در `@media print` هم با همین راه رفع شد.)
2. **`require` سراسری `clinic.php` در bootstrap** (واقعی): هر خطای نحوی در فایل ۸۶KB من، کل سایت (حتی صفحه ورود) را سفید می‌کرد. **رفع:** لود تنبل در `index.php` به سبک هم‌مسیر؛ ثابت شد `layout/login` هیچ تابعی از مطب صدا نمی‌زنند (grep = صفر).
3. **داده `hammasir/store.json` داخل گیت** (واقعی): دیپلوی کامل پوشه، داده هم‌مسیر سرور را با نسخه دمو بازنویسی می‌کرد. **رفع:** از گیت حذف + gitignore شد (ثابت شد هم‌مسیر بدون آن خودش را می‌سازد: `hammasir_store_load` خط ۲۵۴).

## ۵. چیزهایی که نمی‌دانم — باید شما بگویید (سؤال‌های همین پیام)
1. **نحوه دیپلوی:** کل پوشه آپلود می‌شود یا فقط فایل‌های تغییرکرده؟ (لیست دقیق فایل‌های مجاز/ممنوعه برای آپلود در بخش ۷)
2. **استیجینگ:** آیا `test` همان محیط تست است؟ اول آنجا بزنیم؟
3. **نسخه PHP هاست؟** (کد با 7.0+ سازگار نوشته شده؛ اگر 5.x باشد باید بگویید)
4. **سایت اصلی** (`mirbolouki.com`) از نظر فنی از ساب‌دامین جداست؟

## ۶. چک‌لیست تست دستی بعد از دیپلوی (۱۵ دقیقه)
1. ورود کاربر جومای قبلی → داشبورد مثل قبل، بدون منوی مطب، بدون به‌هم‌ریختگی استایل
2. ثبت‌نام کاربر جدید جوما → عادی
3. صفحه هم‌مسیر برای کاربر قبلی → مثل قبل
4. ورود `matab_admin` → منوی مطب دیده می‌شود + جوما سر جایش است
5. ساخت لینک پذیرش → باز کردن در مرورگر ناشناس → پر کردن هر ۵ بخش → ثبت
6. ورود با موبایل/رمز مراجع → پیشخوان مراجع
7. ثبت نوبت + پرداخت + رسید چاپی
8. خروج و ورود مجدد همه نقش‌ها
