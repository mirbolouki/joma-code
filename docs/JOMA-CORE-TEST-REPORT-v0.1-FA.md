### پوشش مجموعهٔ قواعد

- UUIDv4 و رد sentinel/نوع نامعتبر؛ نمونه‌گیری ۱۰۰ UUID تولیدی و بررسی قالب/تکرار در همان نمونه؛ این آزمایش اثبات رمزنگاری یا عدم برخورد همیشگی نیست.
- زمان دقیق UTC، میکروثانیه، تاریخ ناممکن، NUL و سال خارج از محدودهٔ DATETIME.
- حساب غیرفعال/قفل‌شده، scope متفاوت، role متعلق به حساب/عضویت دیگر، ابطال و مرز انقضا، عدم تجمیع مجوز نقش‌ها.
- پذیرش فقط درمانگر واگذارشده؛ رد وضعیت پایان‌یافته، Case قبلاً متصل و اطلاعات ارتباطی ناقص.
- hold پس از engagement فعال، حد دقیق ۱۵ دقیقه، رد یک میکروثانیه بیشتر، انقضا، نوبت مجاور/متداخل، Case/offering اشتباه و مصرف دوباره.
- idempotency برای actor/scope/payload یکسان، تعارض payload، وضعیت PROCESSING؛ نه lookup/transaction واقعی.
- نویسندهٔ PrivateNote بدون الزام عضویت مرکز سابق و بدون استثنای مدیریتی.
- انتشار نسخهٔ مشخص + مخاطب صریح؛ رد پیش‌نویس/دادهٔ خام/یادداشت خصوصی، تحویل حضوری به‌جای portal، نسخهٔ متفاوت، انتشار آینده و ابطال.
- entitlement محصول/ذی‌نفع/منبع معتبر، بدون جایگزینی انتشار با پرداخت.
- نمایندهٔ همان شخص/محدوده/عمل؛ ابطال/انقضا، محدودیت همان Case/خدمت، عدم سرایت به Case دیگر و fail-closed وقتی محدودیت‌ها بارگذاری نشده‌اند یا نوع دادهٔ آن‌ها غلط است.
- عدم تغییر آرایه‌های ورودی در فراخوانی قواعد.

## اجرای تکرارپذیر

از ریشهٔ repository با PHP 64-bit 8.1+:

```sh
php tests/joma_core_lint.php
php tests/joma_domain_rules.php
python tests/joma_schema_static.py
python tests/joma_mariadb_static.py
```

جایگزین توسعه‌ای استفاده‌شده در این محیط، به علت نبود PHP native:

```sh
npm ci --prefix tools --no-audit --no-fund
PHP=8.1 tools/node_modules/.bin/php-wasm-cli tests/joma_core_lint.php
PHP=8.1 tools/node_modules/.bin/php-wasm-cli tests/joma_domain_rules.php
PHP=8.4 tools/node_modules/.bin/php-wasm-cli tests/joma_core_lint.php
PHP=8.4 tools/node_modules/.bin/php-wasm-cli tests/joma_domain_rules.php
```

Node این محیط 22.22.3 و npm 10.9.8 بود. نصب ابزار WASM هشدار engine داد، چون چند بسته Node ≥24.18 و npm ≥11.16 می‌خواهند؛ با این حال اجراهای بالا کامل و موفق شدند. این موفقیت ادعای پشتیبانی رسمی ابزار از Node 22 نیست؛ برای محیط توسعهٔ تکرارپذیر جدید، engineهای اعلام‌شدهٔ بسته‌ها رعایت شوند. هاست برای این قواعد به Node، npm یا Composer احتیاج ندارد.

## چیزهایی که هنوز آزموده نشده‌اند

- SQL adapterهای جدید، transaction پذیرش، constraintهای واقعی زیر بار نوشتن، rollback میان‌مرحله‌ای، دو اتصال هم‌زمان، deadlock/retry و رزرو ظرفیت.
- ورود با گذرواژه، session، CSRF، بازیابی، authorization سراسری endpointها، فایل عمومی/خصوصی و cache.
- رمزنگاری و نگهداری کلید، انتقال/بازیابی یادداشت خصوصی یا امنیت استقرار.
- اجرای همین قواعد در PHP واقعی دامنه. برابر بودن شمارهٔ PHP WASM با **8.1.34** مشاهده‌شدهٔ دامنه، برابری محیط و extensions یا پشتیبانی امنیتی آن نسخه را ثابت نمی‌کند.

## تفکیک از شواهد قبلی هاست

طبق تصاویر ارسالی کاربر، بررسی read-only هاست قبلاً ۷۰ جدول/InnoDB/collation، ۱۷۳ FK با RESTRICT/RESTRICT، ۷۲ UNIQUE و ۹۰ CHECK صریح را تأیید کرده بود. شمار SQL برابر **۱۰۴ CHECK** شامل ۱۴ بررسی خودکار JSON MariaDB بود. دامنه PHP **8.1.34** و MariaDB **10.11.19** نشان داد؛ PHP 8.4.24 در phpMyAdmin محیط دیگری بود.

کاربر حذف ابزارهای موقت بررسی را تأیید کرده است؛ از طرف ما تست مستقل HTTP پس از حذف انجام نشده است. هیچ rollback/write/concurrency test روی هاست اجرا نشده. در این مرحله نیز هاست و دیتابیس تغییر نکرده‌اند. همهٔ داده‌ها/فایل‌های قدیمی به تصریح کاربر آزمایشی و قابل حذف‌اند؛ این مجوز به معنی انجام حذف نیست.

**جمع‌بندی:** قواعد مرجع قابل اجرا و تست شده‌اند؛ برنامهٔ قابل بهره‌برداری، ورود و رزرو اتمیک هنوز تکمیل نشده‌اند. نقشهٔ اتصال و معیار آزمون مرحلهٔ بعد در `JOMA-SERVICE-CONTRACTS-v0.1-FA.md` است.
