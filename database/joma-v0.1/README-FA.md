# راهنمای بستهٔ شمای فیزیکی جوما v0.1

**این بسته را روی دیتابیس زنده یا نصب فعلی کلینیک وارد نکنید.** نامزد طراحی/تست روی یک دیتابیس تازه است، نه آپدیت نرم‌افزار موجود.

## از کجا شروع کنم؟

۱. سند `docs/JOMA-PHYSICAL-SCHEMA-v0.1-FA.md` را بخوانید.
۲. در phpMyAdmin، نسخه و نوع موتور دیتابیس را بررسی کنید. فایل `database/joma-v0.1/000_preflight_readonly.sql` فقط اطلاعات محیط را می‌خواند؛ چیزی نمی‌سازد یا تغییر نمی‌دهد.
۳. هدف این DDL فقط Oracle MySQL 8.0.16+ با InnoDB، charset utf8mb4 و collation utf8mb4_unicode_ci است. MySQL قدیمی‌تر یا MariaDB فعلاً تأیید نشده‌اند.
۴. تنها در پایگاه آزمایشی تازه و خالی، `001_core.sql` بررسی/اجرا شود. اطلاعات واقعی مراجع، رمز دیتابیس یا API key وارد بسته/گفتگو نشود.
۵. فایل `VALIDATION.md` تفکیک بررسی انجام‌شده و تست‌های موتورِ انجام‌نشده را نشان می‌دهد.

## چه چیزهایی تحویل داده شده؟

- ۷۰ جدول، ۱۷۳ FK با RESTRICT، ۹۰ CHECK و ۷۲ UNIQUE علاوه بر کلیدهای اصلی؛
- ۹ نمای ERD فیزیکی از همان منبع تولید DDL؛
- Session بدون نوبت و حداکثر یک Session برای هر نوبت؛
- JSON نسخه‌دار تعریف/پاسخ فرم و مخاطب صریح فرم/گزارش؛
- شناسه اصلی UUIDv4 در BINARY(16)، Lookup عددی؛
- ۱۸ بررسی ساختاری موفق؛ بدون ادعای اجرای MySQL یا امنیت محصول.

## محدودیت‌های ضروری

- ایندکس زمانی، به‌تنهایی مانع تداخل نیست؛ قرارداد قفل ردیف منبع و تراکنش در سند اصلی آمده است.
- این فایل idempotent نیست و DDL در MySQL auto-commit دارد. شکست میانی را با ادامه دادن یا غیرفعال‌کردن FK پنهان نکنید.
- جداول قدیمی clinic_* مهاجرت نمی‌شوند. هیچ DROP/TRUNCATE یا اطلاعات واقعی در بسته نیست.
- payload/کلید/بازیابی یادداشت خصوصی، خام موتور آزمون و دفترکل/کیف‌پولِ تصویب‌نشده عمداً اضافه نشده‌اند.
- طرح schema به‌تنهایی دسترسی endpointها، رمزنگاری، تاریخچه تغییرناپذیر یا عدم deadlock را تضمین نمی‌کند.
- ابزار Python فقط برای تولید/بررسی در محیط توسعه است؛ نصب محصول روی هاست به Python، Composer یا shell نیازمند نشده است.
