# JOMA core — reference rules, v0.1

این پوشه مستقل از برنامهٔ قدیمی `clinic-app` است. **قابل نصب به‌عنوان برنامهٔ آماده نیست؛ هیچ endpoint، ورود، SQL adapter یا رمزنگاری در آن پیاده نشده است.**

- `domain_rules.php`: قواعد کوچک و تابع‌محور، بدون وابستگی به Composer، بدون نوشتن در دیتابیس یا فایل.
- `../tests/joma_domain_rules.php`: داده‌های کاملاً ساختگی در خود فایل و آزمون‌های تکرارپذیر.
- `../docs/JOMA-SERVICE-CONTRACTS-v0.1-FA.md`: قرارداد خدمات، مرز قواعد موجود و اتصال‌های اجرا‌نشده.
- `../docs/JOMA-CORE-TEST-REPORT-v0.1-FA.md`: نتایج و محدودیت آزمون‌ها.

## اجرای محلی برای توسعه‌دهنده

PHP 8.1+، محیط 64-bit؛ بدون دیتابیس:

```sh
php tests/joma_core_lint.php
php tests/joma_domain_rules.php
```

خروج صفر یعنی آزمون‌ها موفق بوده‌اند. هشدار PHP نیز در آزمون به شکست تبدیل می‌شود. آزمون تولید UUID صرفاً نمونه‌گیری است، نه اثبات عدم برخورد یا ممیزی رمزنگاری.

اگر PHP محلی موجود نیست، ابزار توسعهٔ اختیاری:

```sh
npm ci --prefix tools
PHP=8.1 tools/node_modules/.bin/php-wasm-cli tests/joma_core_lint.php
PHP=8.1 tools/node_modules/.bin/php-wasm-cli tests/joma_domain_rules.php
```

Node/npm فقط ابزار تست محلی است و جزو نیازمندی‌های هاست نیست. نسخهٔ Node باید با engine بسته‌های tools سازگار باشد؛ وضعیت محیط استفاده‌شده در گزارش ثبت شده است. هیچ‌کدام از تست‌ها یا tools را در document root هاست قرار ندهید.

## اخطار مهم برای اتصال آینده

آرایه‌های ورودی **تصویر معتبر سمت سرور از وضعیت جاری** هستند، نه JSON ارسالی کاربر. `allowed=true` فقط عبور از همان قاعده است؛ به‌تنهایی احراز هویت، مجوز کامل، ظرفیت آزاد، موفقیت تراکنش یا اجازهٔ رمزگشایی نیست. UUIDهای تست شناسه‌های ساختگی‌اند، نه حساب‌های اولیه. نقش، permission و `policy_status` در تست فقط فرض‌های صریح آزمون‌اند؛ به معنای تصویب سیاست‌های باز، ایجاد نقش در دیتابیس یا فعال‌کردن محصول نیستند.
