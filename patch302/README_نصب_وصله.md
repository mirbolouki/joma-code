# وصلهٔ ۳.۰.۲

دو چیز در یک بسته:

۱. **ویرایش نقش کاربران توسط مدیر** (نیاز شما).
۲. **اصلاح پیام ردِ دسترسی به پرونده** (یافتهٔ آزمون ۱ شما).

## بدون تغییر پایگاه داده
فایل ارتقا ندارد، SQL ندارد، دکمه‌ای برای زدن نیست. فقط ۵ فایل جایگزین/اضافه می‌شود.
اگر وصلهٔ ۳.۰.۱ را قبلاً نصب کرده‌اید، همین بسته روی آن می‌نشیند و جایگزینش می‌شود.

## فایل‌ها
| فایل | مسیر | کار |
|---|---|---|
| `user_roles.php` | `public_html/admin/` | **جدید** — صفحهٔ ویرایش نقش‌ها |
| `users_list.php` | `public_html/admin/` | جایگزینی — دکمهٔ «🔑 نقش‌ها» |
| `account_functions.php` | `public_html/includes/` | جایگزینی — منطق نقش‌ها |
| `case_view_functions.php` | `public_html/includes/` | جایگزینی — پیام یکسان رد دسترسی |
| `footer.php` | `public_html/templates/` | جایگزینی — نشانگر نسخه ۳.۰.۲ |

پس از نصب، پاورقی باید بخواند **«نسخهٔ ۳.۰.۲ (فاز ۳ — پروندهٔ بالینی)»**.

## ۱) ویرایش نقش کاربران
مدیریت ← کاربران ← «🔑 نقش‌ها» ← تیک نقش‌ها ← ذخیره. تغییر بلافاصله اثر می‌کند؛
کاربر لازم نیست خارج و وارد شود.

نگهبان‌های ایمنی (قابل برداشتن، اگر بخواهید):
* دست‌کم یک نقش باید بماند (برای قطع دسترسی «غیرفعال‌سازی» هست).
* نمی‌توانید نقش «مدیر» را از حساب خودتان بردارید.
* آخرین مدیر فعال سامانه نقش مدیرش را از دست نمی‌دهد.

نقش‌ها حذف فیزیکی نمی‌شوند (`REVOKED` می‌شوند). هر اعطا/ابطال با کد
`ROLE_GRANTED` / `ROLE_REVOKED` در گزارش حسابرسی ثبت می‌شود.

## ۲) اصلاح پیام رد دسترسی (نقص D4)
در آزمون ۱ شما، درمانگر ب که نشانی یادداشت درمانگر الف را باز کرد، پیام
«شما درمانگر مسئول این پرونده نیستید» گرفت. **جلوگیری درست کار کرد** —
ولی آن پیام تأیید می‌کرد که «این شمارهٔ پرونده واقعاً وجود دارد». حالا هر دو حالتِ
«پرونده نیست» و «پرونده مال شما نیست» پیام یکسان می‌دهند:

> پرونده یافت نشد یا شما اجازهٔ دسترسی به آن را ندارید.

ثبت رویداد `CASE_ACCESS_DENIED` در حسابرسی دست‌نخورده باقی مانده است.

## وضعیت آزمون — صادقانه
محیط ساخت PHP/MySQL ندارد. فقط بررسی ایستا: ۵۸ فایل PHP بدون خطای نحوی،
و بررسی تطابق پارامترهای ۱۱۹ فراخوانی پایگاه داده. **۰ آزمون اجرایی از سوی من.**
