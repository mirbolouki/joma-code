# راهنمای به‌روزرسانی پیامکی کلینیک — نسخهٔ آزمایشی ۲.۱

این بسته برای برنامهٔ نصب‌شده از `clinic-v2-upload.zip` تهیه شده است. نصب مجدد نیست. فایل نصب، دیتابیس، کلید API یا اطلاعات واقعی مراجعان در بسته نیست.

## قابلیت‌های این نسخه

- ثبت‌نام مراجع با کد تأیید پیامکی، سپس تعیین رمز و ورودهای بعدی با شماره و رمز.
- فراموشی رمز: تأیید کد پیامکی، تعیین رمز جدید و ورود. رمز قبلی ارسال نمی‌شود.
- ساخت پروندهٔ اولیهٔ مراجع جدید بدون پزشک؛ مدیر/منشی ارشد بعداً پزشک را تعیین می‌کند.
- دعوت‌نامهٔ وابسته به پزشک و شماره همراه؛ شماره قبل از نمایش فرم تأیید می‌شود. دعوت با شماره خالی دیگر پذیرفته نیست.
- دعوت جدید ۷ روز اعتبار دارد. پس از ثبت نهایی فرم مصرف می‌شود.
- حساب و پرونده با همان شماره تکرار نمی‌شود؛ تعارض حساب یا پزشک متوقف می‌شود تا مطب بررسی کند.
- ارسال لینک فرم به پرونده‌های موجود، و متن دلخواه توسط مدیر/منشی به پرونده‌های مجاز.
- تنظیمات sms.ir از پنل مدیر؛ گزارش ۲۰۰ درخواست اخیر با شماره پوشیده، بدون متن پیامک، کلید API یا کد محرمانه.
- لینک‌های راهنما به سایت تست و جوما؛ این لینک‌ها ورود یکپارچه یا انتقال نتیجه نیستند.
- کد ۶ رقمی با اعتبار ۵ دقیقه و حداکثر ۵ تلاش؛ ارسال مجدد بعد از ۹۰ ثانیه؛ محدودیت شماره و IP مستقل از کوکی.
- محدودیت اولیهٔ محافظ هزینه: حداکثر ۱۰۰ درخواست ارسال جدید این افزونه در ۲۴ ساعت برای کل سایت. برای افزایش، پس از آزمون باید تنظیم کد بررسی شود.

## موارد انجام‌نشده

- اتصال تست، تفسیر پیشرفته، پکیج تمرین، پرداخت و انتشار پزشک؛ منتظر نسخهٔ نهایی سایت تست هستیم.
- زمان‌بندی یادآوری ۲۴ ساعت قبل از نوبت و ارسال خودکار لینک هنگام تغییر وضعیت نوبت.
- فرم‌ساز و فرم‌های جدید، ذخیرهٔ پیش‌نویس مرحله‌ای و ورود یکپارچه به سایت‌های دیگر.
- استعلام رسیدن پیامک به گوشی. وضعیت موفق یعنی پذیرش درخواست توسط سرویس، نه تحویل قطعی.

## پیش از شروع

این نسخه هنوز با حساب واقعی sms.ir و MySQL هاست شما آزمایش نشده است. ۵۲ بررسی با PHP اجرا شده‌اند، ولی سرویس پیامکی و دیتابیس در آزمون‌های منطق جایگزین آزمایشی داشته‌اند. بنابراین ابتدا فقط با شماره خودتان و اطلاعات ساختگی تست کنید. این بسته تأیید جامع امنیت همهٔ کد قدیمی نیست.

از پشتیبان بخواهید PHP 8.3، افزونه‌های mysqli، mbstring، curl، json و session فعال باشند. ارتباط HTTPS خروجی هاست به api.sms.ir و گواهی‌های معتبر CA لازم است. بررسی SSL را غیرفعال نکنید.

## مرحله ۱: پشتیبان‌گیری

۱. از پوشه `/home/mirbolouki/my` نسخهٔ پشتیبان بگیرید و خارج از مسیر عمومی یا روی کامپیوتر نگه دارید.
۲. از دیتابیس `mirbolouki_clinic` هم بکاپ بگیرید (نام واقعی خودتان را بررسی کنید).
۳. هنگام آپدیت کسی در حال کار با برنامه نباشد؛ بهتر است پشتیبان دسترسی عمومی را موقتاً محدود کند.
۴. فایل `install.php` نباید روی هاست باقی مانده باشد.

## مرحله ۲: آپلود بستهٔ به‌روزرسانی

۱. فایل `clinic-sms-update-v2.1.zip` را دانلود کنید.
۲. در File Manager وارد `/home/mirbolouki/my` شوید.
۳. زیپ را در همین پوشه آپلود و Extract کنید؛ اجازهٔ جایگزینی فایل‌های هم‌نام برنامه لازم است.
۴. پوشهٔ اصلی my، config و data را حذف نکنید. فقط فایل‌ها روی نسخه قبلی قرار می‌گیرند.
۵. فایل‌های واقعی `config/clinic_db.php`، `config/config.php` و `data/clinic_installed.lock` داخل بسته نیستند و نباید تغییر کنند.
۶. اگر قبلاً `data/.htaccess` را شخصی‌سازی کرده‌اید، از پشتیبان بخواهید قانون منع دسترسی بسته را با تنظیم قبلی ادغام کند.
۷. زیپ آپلودشده را بعد از استخراج حذف کنید.
۸. خروج کاربران قبلی پس از آپدیت طبیعی است؛ باید دوباره با رمز وارد شوند.

نصب‌کننده را دوباره اجرا نکنید و SQL وارد نکنید. این افزونه جدول جدیدی نمی‌سازد و از جدول‌های موجود استفاده می‌کند.

## مرحله ۳: محافظت هاست

بسته شامل `data/.htaccess` با `Require all denied` است. این محافظت برای Apache 2.4 / LiteSpeed سازگار است؛ برای Nginx باید پشتیبان تنظیم معادل اعمال کند. دسترسی مستقیم HTTP به config و data، از جمله فایل‌های نشست و گزارش داخلی، باید مسدود باشد و دسترسی PHP برقرار بماند. مجوز پوشه را 777 نکنید.

برای بررسی محافظت: یک فایل متنی بی‌خطر با نام `protection-check.txt` و متن `test` در data بسازید و از مرورگر آدرس `https://my.mirbolouki.com/data/protection-check.txt` را باز کنید. نباید متن نمایش داده شود (معمولاً 403). سپس فایل آزمایش را حذف کنید. همین بررسی را با یک فایل PHP بی‌خطر در config و کمک پشتیبان انجام دهید. اطلاعات یا فایل تنظیمات واقعی را برای آزمایش نمایش ندهید.

از پشتیبان بخواهید HTTPS اجباری و تنظیمات PHP زیر فعال باشد، بدون بازنویسی سایر تنظیمات:

```
display_errors=Off
zend.exception_ignore_args=On
```

اتصال امن کوکی بر اساس HTTPS سرور تشخیص داده می‌شود. اگر TLS پشت پراکسی پایان می‌یابد، از پشتیبان بخواهید HTTPS را برای PHP درست اعلام کند؛ به هدرهای دلخواه بازدیدکننده اعتماد نشود.

## مرحله ۴: ساخت دو قالب در sms.ir

### قالب کد تأیید

نوع: کد یک‌بارمصرف. متن پیشنهادی:

```
کلینیک میربلوکی
کد تأیید شما: #CODE#
این کد را در اختیار دیگران قرار ندهید.
```

نام پارامتر `CODE` است. شناسهٔ قالب واقعی حساب خودتان را پس از تأیید یادداشت کنید؛ شناسهٔ نمونهٔ مستندات را وارد نکنید.

### قالب دعوت

نوع: اطلاع‌رسانی. متن پیشنهادی:

```
کلینیک میربلوکی
برای تکمیل فرم پذیرش وارد لینک اختصاصی زیر شوید:
https://my.mirbolouki.com/index.php?i=#TOKEN#
```

نام پارامتر `TOKEN` است. آدرس دامنه و مسیر داخل متن ثابت قالب‌اند؛ فقط شناسهٔ ۲۴ نویسه‌ای جایگزین می‌شود تا محدودیت ۲۵ کاراکتر رعایت شود. کل لینک را پارامتر قرار ندهید.

اجازهٔ قراردادن لینک این دامنه و تأیید متن را از sms.ir بگیرید. قالب‌های در انتظار/ردشده کار نمی‌کنند. در صورت تفاوت حروف بزرگ/کوچک پارامتر، عین نام ثبت‌شده را در برنامه وارد کنید.

## مرحله ۵: واردکردن تنظیمات در کلینیک

۱. با حساب مدیر وارد شوید:
`https://my.mirbolouki.com/index.php?p=clinic_login`

۲. در پیشخوان، دکمهٔ «پیامک، دعوت‌نامه و تنظیمات sms.ir» را بزنید. آدرس مستقیم:
`https://my.mirbolouki.com/index.php?p=clinic_sms`

۳. کلید API را از پنل خودتان در کادر کلید وارد کنید؛ برای کسی ارسال نکنید.
۴. شناسه قالب کد و نام پارامتر `CODE` را بنویسید.
۵. شناسه قالب دعوت و نام پارامتر `TOKEN` را بنویسید.
۶. تیک «فعال‌بودن ارسال پیامک و کد تأیید» را بزنید و ذخیره کنید.
۷. کلید ذخیره‌شده دوباره نمایش داده نمی‌شود؛ خالی‌گذاشتن کادر در ذخیره‌های بعدی یعنی بدون تغییر.

کلید در فایل محافظت‌شده `config/clinic_sms.php` ذخیره می‌شود. پوشه config باید برای PHP قابل نوشتن باشد. حتماً از محافظت دسترسی وب آن مطمئن شوید.

## مرحله ۶: تست ثبت‌نام با شماره خودتان

۱. در پنجره ناشناس مرورگر، صفحه ورود را باز کنید.
۲. «ثبت‌نام مراجع با تأیید پیامکی» را بزنید.
۳. شماره‌ای متعلق به خودتان وارد کنید که شماره حساب مدیر/پزشک/منشی نباشد.
۴. ارسال کد را بزنید، سپس کد دریافتی را تأیید کنید.
۵. نام، نام خانوادگی و رمز جدید حداقل ۱۰ نویسه‌ای تعیین کنید. برای رمز از انگلیسی استفاده کنید؛ حداکثر ۷۲ بایت.
۶. باید وارد پیشخوان شوید و گزینهٔ تکمیل فرم را ببینید.
۷. با اطلاعات ساختگی فرم را تکمیل کنید.
۸. خارج شوید و با شماره و رمز وارد شوید.
۹. گزینه فراموشی رمز را آزمایش کنید؛ پس از تأیید کد، رمز جدید ثبت و ورود انجام می‌شود. رمز قبلی دیگر نباید کار کند.

## مرحله ۷: تعیین پزشک برای ثبت‌نام مستقیم

مدیر یا منشی ارشد در فهرست پرونده‌ها، پروندهٔ جدید را باز می‌کند. در ویرایش اطلاعات پایه، پزشک را انتخاب و ذخیره می‌کند. تا تعیین پزشک، هیچ پزشک عادی نباید آن پروندهٔ بدون تخصیص را ببیند.

## مرحله ۸: آزمون دعوت

۱. برای یک شماره آزمایشی دیگر پرونده اولیه بسازید و پزشک را تعیین کنید.
۲. وارد صفحه پیامک شوید؛ پرونده و شماره مقصد را انتخاب کنید.
۳. «ارسال لینک فرم پذیرش» را بزنید.
۴. لینک را در مرورگر ناشناس باز کنید. قبل از نمایش فرم، تأیید پیامکی شماره الزامی است.
۵. کد را تأیید کنید و رمز ورود تعیین کنید. در این نسخه، مسیر دعوت بعد از تأیید شماره مرحلهٔ تعیین رمز جدید دارد، حتی اگر حساب مراجع از قبل موجود باشد.
۶. فرم را تکمیل کنید؛ باید همان پرونده به‌روز شود، نه پرونده‌ای جدید.
۷. شمارهٔ داخل فرم، هویت پرونده را تغییر نمی‌دهد؛ شماره تأییدشده از سمت سرور حفظ می‌شود.

ساخت لینک و کپی دستی از بخش پرونده‌ها همچنان ممکن است؛ شماره همراه دعوت اکنون الزامی است. لینک‌های قدیمیِ بدون شماره باید دوباره صادر شوند.

## مرحله ۹: پیامک متن دلخواه منشی

۱. از پشتیبانی sms.ir تأیید بگیرید خط شما اجازهٔ ارسال متن دلخواه از API را دارد.
۲. مدیر در تنظیمات پیامک، نام کاربری sms.ir و شماره خط را وارد و تیک متن دلخواه را فعال می‌کند.
۳. منشی در صفحه پیامک، پرونده و شماره را انتخاب می‌کند، متن را می‌نویسد و تأیید بررسی متن/مقصد را تیک می‌زند.
۴. دکمه «ارسال متن دلخواه» را می‌زند.
۵. ابتدا فقط با شماره خودتان آزمایش کنید. ارسال متن دلخواه لزوماً به شماره‌های مسدودکننده تبلیغات نمی‌رسد؛ با VERIFY فرق دارد.

این بخش از روش POST فرم به `/v1/send` مطابق مستندات ارسالی استفاده می‌کند؛ کلید در URL قرار نمی‌گیرد. در صورت ناسازگاری حساب با این روش، متن دقیق خطای بدون کلید را از پنل سرویس تهیه کنید؛ فعال‌سازی باید با حساب واقعی آزموده شود.

## مرحله ۱۰: کنترل نهایی

- هیچ اطلاعات بالینی واقعی در پیامک یا تست اولیه وارد نکنید.
- با حساب منشی مطمئن شوید پرونده پزشک دیگر و اطلاعات بالینی خصوصی قابل مشاهده نیست.
- با پزشک مربوطه، نمایش فرم پرونده را بررسی کنید.
- دریافت پیامک، کد اشتباه، کد منقضی و تغییر رمز را امتحان کنید.
- مدیر گزارش درخواست‌ها را از پایین صفحه پیامک می‌بیند؛ وضعیت پذیرش با تحویل قطعی اشتباه نشود.
- در تنظیمات قدیمی مطب، حالت یادآوری را فعلاً روی دستی نگه دارید. تنظیم URL قدیمی برای اتصال جدید لازم نیست؛ کد احراز هویت را از آن مسیر ارسال نکنید.
- پشتیبان‌گیری از دیتابیس، config و data را منظم و خارج از مسیر عمومی نگه دارید.

## رفع خطا و بازگشت

- کد ارسال نمی‌شود: فعال‌بودن تنظیمات، اعتبار پنل، تأیید قالب، نام دقیق پارامتر، کلید API و ارتباط cURL را بررسی کنید.
- پیام محدودیت: ۹۰ ثانیه فاصلهٔ ارسال، حداکثر ۵ درخواست ساعتی و ۱۰ درخواست روزانه برای شماره، و سقف عمومی برقرار است؛ فایل محدودیت را برای دورزدن پاک نکنید.
- در خطای ارتباط، قبل از ارسال مجدد، پنل sms.ir را بررسی کنید؛ ممکن است پیام پذیرفته شده ولی پاسخ به هاست نرسیده باشد.
- پیام «بررسی اتصال پرونده»: حساب‌های متعارض یا پزشک متفاوت را خودکار ادغام نکنید؛ مدیر باید بررسی کند.
- اگر 500 دیدید، فقط خط اصلی گزارش PHP را بدون رمز/Stack trace ارسال کنید.
- برای بازگشت، ارسال را غیرفعال کنید و در زمان توقف استفاده، فایل‌های قبل از آپدیت را از بکاپ برگردانید. دیتابیس را بدون بررسی و بکاپ اطلاعات تازه برنگردانید. چون جدول جدیدی اضافه نشده، حذف جدول لازم نیست. فایل‌های جدید بلااستفاده را پشتیبان می‌تواند بعداً جمع‌آوری کند.
