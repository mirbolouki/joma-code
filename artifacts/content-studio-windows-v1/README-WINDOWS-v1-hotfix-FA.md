# راهنمای اجرای محلی Content Studio v1 در Windows

## این بسته چیست؟

این ZIP، خودِ کد فعلی Content Studio را همراه با راه‌انداز Windows و دادهٔ نمایشی synthetic می‌آورد؛ صفحهٔ ساختگی یا یک تصویر نمایشیِ تنها نیست. مسیر واقعی برنامه و renderer اصلی `@napi-rs/canvas@1.0.13` استفاده می‌شود. برنامه در این بسته روی همین رایانه، با SQLite، اجرا می‌شود و برای حالت محلی به Docker، PostgreSQL، Redis، کلید API یا سرویس پولی نیاز ندارد.

این یک **بستهٔ ارزیابی محلی TEST_ONLY** است، نه نسخهٔ آمادهٔ انتشار عمومی. متن و تصویر نمونه ساختگی‌اند؛ تمام درخواست‌های تغییردهنده در این اجرا با برچسب `TEST_ONLY` ثبت می‌شوند. ZIP خروجی نیز آزمایشی است، وضعیت پروژه `NEEDS_REVIEW` می‌ماند و فرم‌های QA تأیید انسانی واقعی یا مجوز انتشار نیستند. هیچ API تولید متن/جست‌وجو/تصویر فعال نیست.

> محیط ساخت در دسترس، Linux است و اجرای native روی Windows در این محیط ممکن نبود. بسته مستقل از Arena Preview آماده شده و مسیر وابستگی Windows در manifest قفل شده است، اما اجرای نهایی روی Windows واقعی هنوز تأیید نشده است. جزئیات این محدودیت در انتهای راهنما آمده است.

## اصلاح راه‌انداز Windows (hotfix)

این بسته مشکل راه‌انداز قبلی را که ممکن بود با پیام `py.exe: No suitable Python runtime found` متوقف شود، اصلاح می‌کند. نسخهٔ قبلی ابتدا شماره‌نسخه‌هایی را امتحان می‌کرد که روی رایانه نصب نبودند؛ این راه‌انداز از Python Launcher به شکل عمومی‌تر استفاده می‌کند و اگر Python واقعاً نصب نباشد، پیام ساده‌تری نشان می‌دهد.

اگر ZIP قبلی را استخراج کرده‌اید، همان پوشه و فایل `.bat` قدیمی را دوباره اجرا نکنید. ZIP این hotfix را در یک پوشهٔ تازه استخراج کنید. پیش از اجرا، Python 3.12+ و Node.js را از بخش پیش‌نیازها نصب کنید.

## پیش‌نیازها

- Windows 11، نسخهٔ ۶۴ بیتی x64. Windows ARM در این ارزیابی پوشش داده نشده است.
- Python نسخهٔ **3.12 یا جدیدتر، ۶۴ بیتی**. نصب Python از python.org و فعال‌بودن Windows Python Launcher (`py`) پیشنهاد می‌شود.
- Node.js نسخهٔ **18 یا جدیدتر، ۶۴ بیتی**؛ نسخهٔ Node.js 22 LTS پیشنهاد می‌شود. نصب‌کنندهٔ Node باید `npm` را هم نصب کند.
- Edge یا Chrome به‌روز.
- اتصال اینترنت در اجرای نخست برای دریافت dependencyهای تعریف‌شده در `pyproject.toml` و `package-lock.json`؛ پس از نصب، برنامه API پولی یا سرویس بیرونی صدا نمی‌زند.
- حدود ۱ گیگابایت فضای خالی برای محیط پایتون، وابستگی‌ها و دادهٔ محلی پیشنهاد می‌شود.

به دسترسی Administrator نیاز نیست. Docker Desktop، PostgreSQL و Redis نصب نکنید؛ این راه‌انداز از آن‌ها استفاده نمی‌کند.

## نصب و شروع

1. ZIP را دانلود و با گزینهٔ **Extract All…** در یک پوشهٔ تازه استخراج کنید؛ مثلاً پوشه‌ای در `Documents`. روی پوشه یا دادهٔ قبلی استخراج نکنید و برنامه را از داخل فایل ZIP اجرا نکنید.
2. اگر Python یا Node.js را همین حالا نصب کردید، پنجره‌های قبلی ترمینال را ببندید تا `py`، `python`، `node` و `npm` در PATH جدید دیده شوند.
3. روی `Start-Content-Studio-Windows.bat` دوبار کلیک کنید. پنجره را باز نگه دارید. اجرای نخست، محیط Python را می‌سازد، dependencyها را از روی manifest/lock نصب می‌کند، دیتابیس محلی را آماده می‌کند و پروژهٔ نمایشی synthetic را ــ اگر موجود نباشد ــ با renderer واقعی می‌سازد. این مرحله بسته به اینترنت چند دقیقه طول می‌کشد؛ دفعات بعد سریع‌تر است.
4. پس از آماده‌شدن demo، در پنجره منتظر پیام Django با عبارت `Starting development server at http://127.0.0.1:8000/` بمانید؛ سپس همین نشانی را در Edge یا Chrome باز کنید. این نشانی محلیِ خود رایانه است، نه Preview.
5. برای ورود:
   - نام کاربری: `studio-tester`
   - گذرواژهٔ آزمایشی: `StudioTestV1!24`
6. برای خاموش‌کردن سرور، در همان پنجره `Ctrl+C` بزنید. بستن پنجره نیز سرور همان اجرا را متوقف می‌کند.

راه‌انداز فقط به `127.0.0.1` گوش می‌دهد؛ آن را به شبکهٔ محلی/اینترنت expose نکنید. رمز بالا فقط برای دادهٔ synthetic این بسته است و نباید در سرویس دیگری استفاده شود.

## آزمودن خروجی

### دیدن پروژهٔ آماده

در صفحهٔ پروژه‌ها، پروژهٔ `TEST_ONLY: چرا با وجود تصمیم جدی، دوباره به عادت قبلی برمی‌گردیم؟` را باز کنید. این پروژه هنگام آماده‌سازی محلی از مسیرهای واقعی برنامه عبور می‌کند و پنج PNG با ابعاد ۱۰۸۰×۱۳۵۰، preview و ZIP می‌سازد. دکمهٔ «ساخت / دانلود ZIP واقعی» را بزنید تا دانلود برنامه را بیازمایید. محتوای آن synthetic و با `TEST_ONLY` علامت‌گذاری شده است.

### ساخت پروژهٔ تازه

1. از صفحهٔ پروژه‌ها، در بخش «پروژهٔ تازه» یک Brand Profile انتخاب و ایده را ثبت کنید.
2. متن مراحل تحریریه را دستی وارد کنید؛ هیچ مدل زبانی متن را تولید نمی‌کند. برای آزمون، دادهٔ ساختگی و بدون اطلاعات شخصی استفاده کنید.
3. Research Decision را دستی ثبت کنید. برای یک تمرین خلاقانهٔ فاقد ادعای factual، می‌توانید «بدون پژوهش بیرونی» را انتخاب و دلیل را بنویسید؛ منبع ساختگی نسازید.
4. متن اسلاید را ثبت کنید. برای رندر، برای هر اسلاید یک تصویر پایهٔ PNG یا JPEG بارگذاری کنید (حداکثر ۱۲ مگابایت) و فقط وقتی واقعاً حق استفاده دارید، گزینهٔ تأیید حقوق استفاده را بزنید. برای تمرین از تصویر ساختگی/خودساختهٔ بی‌متن استفاده کنید؛ تصویر مراجعه‌کننده، مشتری، بیمار یا شخص دیگر بارگذاری نکنید.
5. دکمهٔ رندر را بزنید و preview را بررسی کنید. renderer محلی متن را روی تصویر پایه می‌چسباند؛ تصویر پایه خروجی AI نیست.
6. اگر می‌خواهید مسیر ZIP را هم بیازمایید، هر سه فرم QA را فقط به‌عنوان آزمون فنی پر کنید و سپس ZIP همان پروژه را دانلود کنید. پاسخ QA در این نسخه تأیید واقعی انسانی، بررسی رسمی سیاست پلتفرم یا اجازهٔ انتشار محسوب نمی‌شود.

**محدودیت فعلی UI:** ویرایش درجا و ذخیرهٔ مجدد متن اسلاید موجود در دسترس نیست؛ برای آزمون می‌توانید اسلاید تازه اضافه کنید. providerهای خودکار متن، جست‌وجو و تصویر نیز خاموش‌اند.

## داده و حریم خصوصی

- دیتابیس، فایل‌های بارگذاری‌شده، PNGها و ZIPها در پوشهٔ `var\user-test-v1\` کنار همین برنامه نگهداری می‌شوند؛ برنامه آن‌ها را به سرویس راه‌دور بارگذاری نمی‌کند.
- راه‌انداز پوشهٔ داده را پاک یا reset نمی‌کند. برای حفظ داده، آن پوشه را نگه دارید و از خود آن یک نسخهٔ پشتیبان بگیرید.
- برای نسخهٔ تازه، ZIP را در یک پوشهٔ تازه استخراج کنید؛ نسخهٔ جدید را روی پوشهٔ دارای `var\user-test-v1` کپی/استخراج نکنید.
- بسته هیچ dump دیتابیس یا فایل ZIP مربوط به Joma/Clinic را در بر ندارد.

## اگر پورت 8000 مشغول بود

سرور را متوقف کنید یا از PowerShell در پوشهٔ استخراج‌شده پورت دیگری انتخاب کنید:

```powershell
$env:STUDIO_TEST_PORT = "8010"
.\Start-Content-Studio-Windows.ps1
```

سپس `http://127.0.0.1:8010/` را باز کنید. برای بازگشت به پیش‌فرض، پنجرهٔ PowerShell را ببندید.

## خطای نصب یا اجرا

- پیام Python/Node را دیدید؟ نسخه و معماری ۶۴ بیتی را بررسی کنید؛ پس از نصب ترمینال را دوباره باز کنید.
- دانلود dependency شکست خورد؟ اتصال اینترنت را بررسی و همان فایل `.bat` را دوباره اجرا کنید؛ نصب تکراری با lock موجود انجام می‌شود.
- اگر برنامه بالا نیامد، پنجره را باز نگه دارید و متن خطای آخر را نگه دارید. نام کاربری و گذرواژه یا مقدار کوکی را در گزارش/تصویر صفحه نفرستید؛ دادهٔ شخصی یا محرمانه هم ارسال نکنید.

## محدودهٔ تأیید

همین ZIP در یک پوشهٔ clean-copy جدا از Arena Preview استخراج و روی سرور loopback محلی اجرا شد. در آن آزمون، `npm ci` و بارگذاری `@napi-rs/canvas@1.0.13` موفق بود؛ `manage.py check` و `makemigrations --check --dry-run` بدون خطا بودند؛ seed واقعی پنج اسلاید رندر کرد؛ `pytest` برابر ۴۴ تست موفق شد؛ و مسیر HTTP محلیِ ورود، صفحهٔ پروژه و دانلود ZIP را با پاسخ ۲۰۰، پنج PNG نهایی و manifest دارای `TEST_ONLY` گذراند. رمز، کوکی و token در خروجی/لاگ چاپ نشدند.

محدودیت مهم: محیط Linux فعلی فقط Python 3.11.2 داشت که **پایین‌تر از حداقل رسمی بسته (Python ≥3.12)** است. برای آن smoke test، محدودیت نسخهٔ Python فقط در نصب موقت محیط اعتبارسنجی نادیده گرفته شد؛ این Python برای استفادهٔ شما توصیه نمی‌شود و آزمون Linux را تأیید native Windows حساب نمی‌کنم. در سابقهٔ همین کار نیز suite روی Python 3.12.15 اجرا شده و ۴۴ تست پاس شده بود، اما Windows واقعی و PowerShell ویندوز در دسترس این نوبت نبودند؛ بنابراین **ادعای اجرای موفق native روی Windows نمی‌کنم** و فایل PowerShell روی خود Windows اجرا نشده است.

پیش‌نیاز عملی برای تأیید کامل Windows، اجرای همین ZIP روی Windows 11 x64 با Python 3.12+ و Node 22 LTS است. بسته به‌صورت ZIP منبع با راه‌انداز Windows تحویل می‌شود، نه فایل EXE خودبسنده؛ اگر اجرای native Windows به مانع بخورد، جایگزین عملی اجرای همان بسته در WSL2 با Python/Node سازگار است، ولی آن مسیر نیز در این نوبت آزموده نشده است.
